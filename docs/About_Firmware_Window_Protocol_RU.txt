Протокол формирования окна «О прошивке» (Form1 -> AlStInfoF)

1) Назначение
Окно «О прошивке» показывает:
- строку версии прошивки (из ответа прошивки по CAN);
- имена Main/Fast/Tooth кадров;
- состояния KUK1/KUK2/KUK3;
- список активных ключей KUK с человекочитаемыми описаниями.

2) Точка входа
- Пункт меню: «О программе» (в главной форме Form1).
- Обработчик: вызов метода InfoFrm() в файле Stepulyov/ASt_MainF.cs.

3) Подготовка данных до открытия окна
3.1. Загрузка справочника KUK
- При инициализации формы вызывается Rkf().
- Rkf() читает config_switch.h/config_switch и заполняет:
  - _k1 (описания kuk1),
  - _k2 (описания kuk2),
  - _k3 (описания kuk3).

3.2. Получение данных от прошивки
- При отсутствии данных InfoFrm() отправляет запрос cmd_128(333) и просит повторить через 1-2 секунды.
- Ответ разбирается в MainWindow.cs:
  - case 32000: накопление текстового блока в _s0;
  - case 32001: разбор блока на поля:
	- KspIdString (версия прошивки),
	- spf.FrameString,
	- sp2.FrameString,
	- служебные части даты/времени (в окно не выводятся);
  - case 32002: получение KUK-битов и установка IdRcvd.

4) Формирование DataTable в InfoFrm()
InfoFrm() создаёт DataTable (колонки PName, PVal) и добавляет строки в порядке:
1. «Версия прошивки:» -> KspIdString (или «нет данных»).
2. Пустая строка-разделитель.
3. «Main кадр:» -> F2Kadr_IniFileName.
4. «Fast кадр:» -> spf.FrameString.
5. «Tooth кадр:» -> sp2.FrameString.
6. Пустая строка-разделитель.
7. «KUK1:» -> Kk1.
8. «KUK2:» -> Kk2.
9. «KUK3:» -> Kk3.
10. Пустая строка-разделитель.
11. Список активных ключей KUK:
	- для каждого бита '1' в Kuk1/Kuk2/Kuk3 берётся строка из _k1/_k2/_k3;
	- слева выводится имя ключа, справа комментарий-описание.

5) Правила определения активных ключей
- Kuk1/Kuk2/Kuk3 — бинарные строки флагов (получены из прошивки).
- Индекс бита сопоставляется с индексом строки в _k1/_k2/_k3.
- Если бит == '1', ключ считается активным и добавляется в таблицу.

6) Отображение формы
- Если форма уже открыта (_infof != null) — повторно не создаётся.
- Иначе создаётся AlStInfoF(dtt), показывается, меню «О программе» временно блокируется.
- При закрытии формы _infof обнуляется, пункт меню снова активируется.

7) UI-поведение AlStInfoF
- Источник грида: DataTable из InfoFrm().
- Столбцы readonly, сортировка отключена, подбор размеров по содержимому.
- Выделение строк/ячеек гасится, визуально это «табличная карточка информации».

8) Ключевые ограничения
- Версия прошивки берётся из CAN-ответа прошивки, не из локальных файлов.
- Корректность списка KUK зависит от формата config_switch(.h).
- Если ответ прошивки ещё не пришёл, окно не заполняется «на лету»: сначала запрос, затем повторный вход.
