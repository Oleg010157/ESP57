# Путь к CCS для ИИ-агента

Этот файл отслеживается git и ездит между машинами. Сами `CLAUDE.md` — нет:
их верхнюю часть пишет CCStudio при запуске, помечая `DO NOT EDIT`, и правка
внутри этого блока не живёт дольше следующего старта IDE.

## Переезд на новую машину: сначала скрипт

Пошаговая памятка для человека — [setup-other-pc-RU.md](setup-other-pc-RU.md).
Ниже — техническая сторона.

Всё, что не едет с git (патчи в установленном C2000Ware, пользовательский
конфиг clangd, ссылка на этот файл в `CLAUDE.md`), восстанавливает один скрипт.
Он идемпотентен — повторный запуск безопасен:

```
powershell -ExecutionPolicy Bypass -File Tools\Setup-NewPC.ps1 -Check
powershell -ExecutionPolicy Bypass -File Tools\Setup-NewPC.ps1
```

Он же сам находит установку C2000Ware и CCS, так что описанный ниже разбор
путей нужен только когда скрипт сообщил об ошибке или машин/версий несколько.
Что именно он делает и почему — `INVERTOR_CCS/my_Files/C2000Ware_local_patches.txt`.

## Окно Watch (Expressions) между машинами

CCStudio хранит выражения не в проекте, а в localStorage Electron:

```
%LOCALAPPDATA%\Texas Instruments\CCS\ccs<версия>\0\electron\Local Storage\leveldb
```

ключом вида `<путь к workspace>:debug:watch`, значение — JSON
`{"expressions":[...],"showPinnedCores":true}`. Отсюда две беды: база лежит
в профиле машины и с git не ездит, а путь внутри ключа означает, что выражения
теряются даже на одной машине при переименовании папки — так и вышло при
`K55` → `K56` → `K57`, старые записи до сих пор лежат в базе мёртвым грузом.

Копировать базу не нужно: в окне Expressions есть штатные **Import / Export**.
Порядок такой — на машине, где выражения есть, Export в
`INVERTOR_CCS/watch_expressions.json` и коммит; на другой машине Import из
этого файла. Так они ездят с репозиторием и не зависят ни от машины, ни от пути.
Диалог просит полный путь вместе с именем файла и расширение сам не подставляет,
а путь этот на каждой машине свой. Готовую строку печатает
`Tools\Setup-NewPC.ps1` — он вычисляет её от собственного расположения,
так что достаточно запустить с `-Check` и скопировать из строки `Watch: выражения`.

## Чем плох сгенерированный путь

CCStudio подставляет туда путь той версии, которая запущена на конкретном
компьютере:

- домашний ПК — только `C:/ti/ccs2100`
- рабочий ПК — сосуществуют `C:/ti/ccs2100` и `C:/ti/ccs2101`

Пока `CLAUDE.md` отслеживался, каждый переезд между ПК давал правку в одну
строку, которой никто не делал, и путь в ней регулярно указывал на
несуществующую на этой машине папку.

## Что делать агенту

**Не доверяй пути из сгенерированного блока вслепую — проверь наличие каталога
на диске.** Если его нет, определи установленные версии и возьми самую новую:

```
ls -d /c/ti/ccs*/ccs/theia/resources/ai/CCS.md
```

Корень найденной установки (`/c/ti/ccsXXXX`) и есть `{ccs-install-dir}`; файл
`CCS.md` из неё читай вместо пути, указанного в `CLAUDE.md`. Если установок
несколько, предпочитай ту, которой соответствует запущенный экземпляр CCS.

Проверить, какая именно версия работает сейчас, можно по путям в логе сборки:
`INVERTOR_CCS/CPU1_RAM/subdir_rules.mk` содержит полный вызов компилятора с
абсолютными путями к той установке, которой собирали в последний раз.

## Как это подключено

В `CLAUDE.md` (в корне и в `INVERTOR_CCS/`) ниже строки
`<!-- User instructions should be added below this line -->` стоит ссылка на
этот файл. Сами `CLAUDE.md` в `.gitignore`.

**На новой машине** после первого запуска CCStudio файл `CLAUDE.md` появится
заново, но уже без этой ссылки — её надо дописать руками, одной строкой:

```
@docs/agents-ccs-path.md
```

В `INVERTOR_CCS/CLAUDE.md` путь на уровень выше: `@../docs/agents-ccs-path.md`.
