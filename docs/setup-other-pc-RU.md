# Работа на другом компьютере: что делать по шагам

Памятка для человека. Технические подробности и «почему так» — в
[agents-ccs-path.md](agents-ccs-path.md) и
`INVERTOR_CCS/my_Files/C2000Ware_local_patches.txt`.

## Первый раз на этой машине

**1. Получить проект.**

```
git clone https://github.com/Oleg010157/P55x.git
```

или, если он уже есть, `git pull`.

**2. Запустить скрипт настройки** — из корня проекта:

```
powershell -ExecutionPolicy Bypass -File Tools\Setup-NewPC.ps1 -Check
powershell -ExecutionPolicy Bypass -File Tools\Setup-NewPC.ps1
```

Первая команда только показывает, чего не хватает; вторая чинит. Запускать
можно сколько угодно раз — повторный запуск ничего не портит.

Скрипт сделает: патчи в установленном C2000Ware (иначе сборка падает на
`SUCCESS`/`FAIL`), конфиг clangd (иначе заголовки SDK серые), ссылки в
`CLAUDE.md`, и создаст `C:\K57` — стабильный путь к проекту.

**3. Открыть проект в CCStudio ЧЕРЕЗ стабильный путь:**

```
File -> Open Workspace...  ->  C:\K57\INVERTOR_CCS\K57.theia-workspace
```

Это главное правило. Не по реальному пути вроде `E:\Work\...`, а именно через
`C:\K57`. Иначе открытые вкладки и выражения Watch привяжутся к реальному пути
и потеряются при первом же переименовании папки.

**4. Восстановить выражения Watch**, если файл есть в репозитории:

```
окно Expressions -> правый клик -> Import
                 -> C:\K57\INVERTOR_CCS\watch_expressions.json
```

**5. Выбрать конфигурацию сборки и собрать:**

```
Project -> Build Configurations -> Set Active -> CPU1_RAM (или CPU1_FLASH)
```

## Каждый следующий раз

Ничего настраивать не нужно. Только:

- `git pull` перед работой, `git push` после;
- открывать проект через `C:\K57\INVERTOR_CCS\K57.theia-workspace`.

## Что переносится, а что нет

| | переносится | как |
|---|---|---|
| Исходники, линкеры, `.cproject`, `.syscfg` | да | git |
| Конфигурация отладки, настройки редактора | да | git (`INVERTOR_CCS/.theia/`) |
| Выражения Watch | да | Export в файл, коммит, Import на другой машине |
| Патчи C2000Ware, конфиг clangd | восстанавливаются | `Tools\Setup-NewPC.ps1` |
| Открытые вкладки, раскладка окон | **нет** | открыть заново |
| История разговоров с Claude Code, его память | **нет** | лежит в профиле машины |

**Junction не синхронизирует компьютеры.** База состояния CCStudio у каждой
машины своя. `C:\K57` даёт лишь то, что ключ в этой базе одинаков: поэтому
вкладки и Watch не теряются между запусками и переживают переименование папки.
Но с рабочей машины на домашнюю они сами не переедут.

## Перенести выражения Watch между машинами

На той машине, где выражения есть:

1. окно Expressions → правый клик → **Export**;
2. в диалоге указать путь целиком (`Browse...` удобнее):
   `C:\K57\INVERTOR_CCS\watch_expressions.json`;
3. проверить, что в файле не просто `[]` — это значило бы, что Watch был пуст;
4. `git add INVERTOR_CCS/watch_expressions.json`, коммит, `git push`.

На другой машине: `git pull`, затем Expressions → **Import** из того же файла.

## Если папку проекта переименовали или перенесли

Junction надо пересоздать — перенаправить его нельзя:

```
rmdir C:\K57
mklink /J C:\K57 <новый реальный путь>
```

`rmdir` снимает только ссылку, файлы по ту сторону не трогает. Удалять через
PowerShell `Remove-Item -Recurse` не надо — он умеет провалиться внутрь и снести
настоящие файлы.

После этого всё состояние CCStudio останется на месте: оно привязано к `C:\K57`,
а не к реальному пути.

## Если окно Claude Code пустое

Значит не выполнен вход. Открыть терминал (`Terminal -> New Terminal`) и
запустить `claude` — он проведёт через авторизацию. Переустанавливать
расширение не нужно, дело не в нём.
