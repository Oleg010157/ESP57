Протокол метода Rkf() (Stepulyov/ASt_MainF.cs)

Назначение
Метод Rkf() загружает из файла config_switch.h (или config_switch) описания ключей условной компиляции KUK1/KUK2/KUK3, чтобы затем показывать их в окне «О программе».

Где вызывается
Rkf() вызывается при инициализации главной формы (в ASt_MainF.cs).

Входные данные
1) Файл: <Application.StartupPath>\config_switch.h
2) Если не найден: <Application.StartupPath>\config_switch

Выходные данные
Заполняются списки строк:
- _k1 — описания из struct kuk1
- _k2 — описания из struct kuk2
- _k3 — описания из struct kuk3

Алгоритм работы
1. Инициализируются флаги секций: b1, b2, b3 = false.
2. Вычисляется путь к config_switch.h; при отсутствии пробуется config_switch без расширения.
3. Если файл не найден — метод завершает работу (return).
4. Файл читается целиком как UTF-8: File.ReadAllLines(path, Encoding.UTF8).
5. Для каждой непустой строки:
   5.1. Если встретилось "struct kuk1 {" -> b1 = true.
   5.2. Если внутри kuk1 встретилась "}" -> b1 = false.
   5.3. Если b1 == true и строка содержит "Uint16" -> строка добавляется в _k1.

   5.4. Аналогично для "struct kuk2 {" / "}" / "Uint16" -> список _k2.
   5.5. Аналогично для "struct kuk3 {" / "}" / "Uint16" -> список _k3.

Использование результата
В InfoFrm() биты Kuk1/Kuk2/Kuk3, полученные из прошивки, сопоставляются с элементами _k1/_k2/_k3.
Если соответствующий бит == '1', описание ключа выводится в окно «О программе».

Ограничения и замечания
- Метод чувствителен к формату файла (ожидаются точные маркеры "struct kukX {" и строки с "Uint16").
- При изменении структуры config_switch список ключей может отображаться некорректно.
- Метод не читает версию прошивки (версия берётся из CAN-ответа прошивки, не из config_switch).
