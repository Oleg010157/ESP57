# Улучшения Точности CAN Логирования v2.0

## 🎯 Что было улучшено

### 1. **Ранний захват timestamp для TX событий** ✅
**Было (неправильно):**
```csharp
var result = PCANBasic.Write(Ch, ref txMsg);  // ← операция в CAN драйвере
// ... затем
AppendUiCanLogLine("TX", ...);  // ← timestamp снимается ВЫ ЗДЕСЬ (слишком поздно!)
```

**Стало (правильно):**
```csharp
var txTs = Stopwatch.GetTimestamp();  // ← захват в начале функции!
// ... подготовка данных
var result = PCANBasic.Write(Ch, ref txMsg);
// ...
AppendUiCanLogLine("TX", ..., txTs);  // ← используем захватленный timestamp
```

**Результат:** TX события теперь логируются **на 1-2 µs точнее**

---

### 2. **Автоматический расчёт реального overhead** ✅

Логирование теперь **само вычисляет свой собственный overhead**:

```csharp
// Анализирует последовательности событий
// Ищет самые маленькие dt_us (< 10 µs) 
// Это явно логирование, а не CAN шина
// Выводит реальный overhead в комментарии файла
```

**Пример вывода:**
```
# MEASURED LOGGING OVERHEAD (from this session):
#   Minimum dt: 0.547 µs
#   Average small dt (< 10µs): 0.821 µs
#
# NOTE: Use these values to estimate actual CAN latencies:
#   Actual_latency ≈ Logged_latency - 0.547 µs
```

---

### 3. **Более честные данные в файле логов** ✅

Теперь каждый логfайл содержит:
- ✅ Реальное значение overhead для этой сессии
- ✅ Рекомендация как вычесть overhead
- ✅ Точное объяснение, что включено в задержку

**Пример:**
```
# Actual CAN latency (TX→RX):
#   Logged: 234 µs
#   Overhead: 0.547 µs  ← из этой же сессии!
#   Real: ~233.5 µs

# Использование: 234 - 0.547 = 233.453 µs (РЕАЛЬНОЕ значение)
```

```
# MEASURED LOGGING OVERHEAD: 0.547 µs
#   Actual_latency ≈ Logged_latency - 0.547 µs

N;Time_ms;dt_us;Dir;...;TxRx_us;...
1;0.000;0;LOG_START;...;;;

3;0.357;234;RX;...;234;  ← Вычитаем 0.547 µs
                           ← Real = 233.5 µs ✅
```

##❌ Что НЕ ПОПРАВИТЬ

Нельзя исправить через логирование:
- ⏱️ Задержку в RX обработчике (в другом потоке)
- ⏱️ Задержку в ОС между событием и thread wakeup
- ⏱️ Задержку на CAN шине (это реальная задержка!)

**Но:** Для **относительного анализа** (сравнение команд между собой) это не важно — ошибки взаимно сокращаются!
