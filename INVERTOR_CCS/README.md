# INVERTOR_CCS — однофазный инвертор на TMS320F28P550SJ9

Прошивка C2000 для инвертора K55. Проект CCS, имя `invertor`, рабочая
конфигурация — `CPU1_FLASH`.

Этот файл нужен для одного: чтобы перенос проекта на другую машину не
превращался в расследование. Половина состояния CCS живёт не в папке проекта,
а в профиле пользователя, и после `git clone` эта половина отсутствует. Ниже —
что именно требуется поставить, как открыть проект, и три грабли, на которые
здесь уже наступили.

---

## Требуемое окружение

Версии не пожелание, а часть проекта: они записаны в `.cproject` и
`.ccsproject`. С другими версиями проект либо не соберётся, либо соберётся
иначе.

| Что | Версия | Где стоит | Чем зафиксировано |
|---|---|---|---|
| CCStudio IDE | 21.0.0.00014 | `C:\TI\ccs2100` | `.ccsproject`: `ccsVersion 71.0.0` |
| C2000Ware | **26.01.00.00** | `C:\TI\C2000Ware_26_01_00_00` | `.cproject`: `C2000WARE:26.1.0.00`, плюс абсолютный путь к `.metadata/sdk.json` в строках 112 и 241 |
| Компилятор C2000 | TI v25.11.1.LTS | `C:\TI\ccs2100\ccs\tools\compiler\ti-cgt-c2000_25.11.1.LTS` | `.cproject`: `toolVersion` |
| SysConfig | 1.28.0 | `C:\TI\ccs2100\ccs\utils\sysconfig_1.28.0` | `.cproject`: `sysconfig:1.28.0` |
| Отладчик | XDS110 | — | `targetConfigs/TMS320F28P550SJ9_LaunchPad.ccxml` |

Версия C2000Ware — самая болезненная привязка. Она вбита в `.cproject`
абсолютным путём вместе с номером версии, поэтому C2000Ware другой версии или
установленный не на `C:` потребует правки проекта. Ставить ту же.

Target configuration лежит **внутри** проекта (`targetConfigs/`), и
`.ccsproject` помечает её как выбранную вручную
(`isTargetConfigurationManual=true`). Это сделано намеренно: глобальный каталог
`~/ti/CCSTargetConfigurations` при переносе не участвует, ccxml едет с
репозиторием.

## Как открыть на новой машине

**Открывать папкой: File → Open Folder → `<путь>\INVERTOR_CCS`.**

Не файлом `K55.theia-workspace` и не `inv.theia-workspace`, хотя оба лежат
рядом и открываются. Причина — в следующем разделе; коротко: открытие папкой
единственный способ, при котором backend CCS гарантированно получает путь к
проекту.

Если после открытия проект виден в Project Explorer как обычная папка, без
иконки проекта — **Project → Import CCS Projects**, указать эту же папку.

Каталоги сборки `CPU1_FLASH/` и `CPU1_RAM/` генерируются и в git не хранятся;
они появятся при первой сборке.

## Грабли, на которые уже наступили

### 1. Меню Project не работает — ни один пункт

Симптом: пункты меню Project отрабатывают вхолостую, сборка ничего не выводит,
ошибок нет.

CCS — это два процесса. Оболочка `ccstudio.exe` (Theia/Electron) рисует
интерфейс, а вся содержательная часть — модель проекта, сборка, свойства,
индексатор CDT, отладка — это headless Eclipse в `ccs-server.exe`, с которым
оболочка говорит через named pipe. Меню Project только пересылает запросы туда.

Список рабочих папок передаётся серверу **один раз, аргументом при его
запуске**:

```
ccs-server.exe ... -ccs.workspaceFolderPaths <пути через ;>
```

Пока открыт workspace-**файл**, до сервера доезжает не путь проекта, а путь по
умолчанию — `C:\Users\<имя>\workspace_ccstheia`, пустая папка. Сервер после
этого просто не знает, что проект существует, и работать ему не над чем.
При открытии **папки** путь присваивается напрямую, и подмены не происходит.

Как убедиться, что дело в этом:

```powershell
Get-CimInstance Win32_Process -Filter "Name='ccs-server.exe'" |
    Select-Object -ExpandProperty CommandLine
```

Если в `-ccs.workspaceFolderPaths` не путь к проекту — это оно.

Лечение: перезапустить CCS и открыть **папку**. Убедиться, что при закрытии
завершились все процессы `ccstudio.exe` и `ccs-server.exe`.

Перезапуск одного лишь `ccs-server.exe` не помогает — проверено. Он поднимается
заново автоматически, за секунды, состояния в нём нет, — но оболочка передаёт
ему ровно тот же путь по умолчанию, и всё остаётся как было. Дефолтный список
папок живёт в оболочке, и заменой сервера его не сбить.

Лог сервера, если понадобится:
`%LOCALAPPDATA%\Texas Instruments\CCS\.ccs-server\workspaces\<hash>\.metadata\.log`

### 2. `error #148` на символах `Ramfuncs*` — уже исправлено, не вернуть обратно

Шесть одинаковых ошибок в `my_Files/main.c`:

```
f28p55x_globalprototypes.h, line 258: error #148: declaration is incompatible
with "uint16_t RamfuncsLoadStart" (declared at line 77 of syscfg/device.h)
```

Это несогласованность внутри C2000Ware 26.01, а не дефект проекта. Символы
линкера `RamfuncsLoadStart … RamfuncsRunSize` объявлены дважды и по-разному:

* `f28p55x_globalprototypes.h:258` — как `Uint16`, а это `unsigned short`
  (`f28p55x_device.h:191`);
* сгенерированный SysConfig `CPU1_FLASH/syscfg/device.h:77` — как `uint16_t`,
  а это для C28x `unsigned int` (`stdint.h` компилятора).

Оба типа 16-битные и беззнаковые, но для компилятора разные. Ошибка возникает
там, где в один файл попадают оба стиля заголовков **и** определён `_FLASH`
(в `device.h` объявления спрятаны под `#ifdef _FLASH`) — то есть только в
`main.c`.

Решение в [my_Files/main.c](my_Files/main.c): битовые поля подключаются
напрямую через `f28p55x_device.h`, а не через `f28x_project.h`. Разница в том,
что `f28x_project.h` тянет `f28p55x_examples.h`, а тот — `globalprototypes.h` с
конфликтующими объявлениями; сам `f28p55x_device.h` его не включает. Ничего из
`examples.h` в `main.c` не используется. Так же подключены битовые поля во всех
файлах K56.

Если когда-нибудь `#include "f28x_project.h"` вернётся в `main.c` — ошибка
вернётся вместе с ним.

### 3. Конфигурация `CPU1_RAM` не линкуется

Компиляция проходит, линковка — нет: `.text` (0x7d2f) не помещается в доступную
RAM, плюс не описана секция `.TI.ramfunc`. Конфигурация давно не используется,
рабочая — `CPU1_FLASH`. Если понадобится RAM-сборка, начинать с
`28p55x_generic_ram_lnk.cmd`.

## Сборка из командной строки

Годится, когда backend CCS не отвечает (грабля №1) или нужен полный вывод
компилятора. Makefile'ы в `CPU1_FLASH/` генерирует сама CCS, так что хотя бы
одна успешная сборка из IDE должна была пройти раньше:

```bash
cd CPU1_FLASH
PATH="/c/TI/ccs2100/ccs/utils/bin:$PATH" gmake.exe all
```

Результат — `CPU1_FLASH/invertor.out` и `invertor.map`.

Флаг `-k` заставит собрать всё, что собирается, и показать ошибки во всех файлах
сразу, а не только в первом упавшем.

## Где лежит состояние CCS

Затем и написан этот файл: половина настроек в профиле пользователя, и при
переносе она не едет.

| Где | Что там | Едет с git |
|---|---|---|
| папка проекта | `.project`, `.cproject`, `.ccsproject`, `.settings/`, `targetConfigs/`, `*.syscfg`, `*.cmd` | да |
| `%LOCALAPPDATA%\Texas Instruments\CCS\.ccs-server\workspaces\<hash>\` | Eclipse-workspace: реестр проектов, индексы CDT | нет |
| `%LOCALAPPDATA%\Texas Instruments\CCS\ccs2100\0\theia\` | настройки IDE, `recentworkspace.json`, доверенные папки | нет |
| `~/ti/CCSTargetConfigurations` | ccxml вне проекта | нет, и не используется — см. выше |

Ничего из второй половины восстанавливать вручную не нужно: она создаётся
заново при первом открытии проекта. Важно лишь, чтобы сервер открылся **на той
папке**, — отсюда правило открывать папкой, а не workspace-файлом.
